## Done
- New package `@decentnetwork/beagle-embed` 0.1.0 in `Decent-Network/beagle-embed` (https://github.com/Decent-Network/beagle-embed), not inside a host app. Published to npm as 0.1.0 public. The package page shows that version. A repeat publish was refused with "cannot publish over the previously published versions: 0.1.0". `npm view` from this machine still 404'd while the page was up.
- `openChat` loads `@decentnetwork/beagle-ui` 0.2.40 and the beagle-web bundle only after the click, inside a same-origin frame.
- Example `example/index.html`. `npm test` passed (3). `npm run measure` on 2026-11-17: 0 heavy bytes before the click; 1,801,858 after **Open in this page**; second tab `lockState.held === false` ("held by another tab"); first tab still held the lock. **Open chat** with Beagle on `127.0.0.1:8766` loaded nothing heavy and returned the installed-app path.

## Decisions
- A new package, because mounting beagle-ui or beagle-web in the host document takes over the page. `mount()` was not modified.
- beagle-web is not an npm dependency. The registry has no such package, and a missing dependency would break install. Hosts pass its URL.
- The frame is `about:blank` plus `document.write`. srcdoc reported `location.origin === "null"`, so each panel would have taken its own lock.
